# 头脑风暴 · 实时数据进阶（请求合并 + 嵌套路径）

> 日期：2026-11-06 · 状态：**待决策**（本文件只做方案设计，不含实现）
> 关联：`docs/图表工作台-第二阶段方案.md` D24（实时数据收口）、计划 T16

## 0. 一句话

现在的实时数据是**每个图表各自打接口、只认「首行表头 + 数据行」的二维表、路径只能点号取值**。
要做到能上真实业务，需要解决三件事：**同一个接口别打 N 次**、**路径能取到嵌套/数组字段**、**返回对象数组也能直接上图**。

---

## 1. 现状事实（读代码 + 实测得出，不是推测）

| # | 事实 | 位置 |
|---|---|---|
| F1 | 每个图表注册一个 `setInterval`，**各自 fetch 自己的 URL**：同一接口被 5 个图表引用 = 每轮 5 次请求 | `core/live/liveExecutor.ts` `register/fetchOne` |
| F2 | `LiveExecutor` 是**实例级**的：工作台一个实例、演示页一个实例；演示轮播每次切屏还会 `setupLive()` 重建 → 重建瞬间会立刻 `tick()` 全量再打一遍 | `WorkbenchView.syncLive` / `PlayView.setupLive` |
| F3 | 请求**没有单飞去重**：`tick()` 与定时器撞在一起就会并发两次同样请求 | `liveExecutor.tick` |
| F4 | 失败**没有退避**：接口挂了就按原间隔一直锤 | `liveExecutor` |
| F5 | 页面切到后台/隐藏时**照常轮询** | 同上 |
| F6 | `resolveDataPath` 只支持点号取值，**不支持数组下标/通配**：`rows.0.value` 能凑合（数组恰好可被数字索引），`rows[*].value` 取不到 | `core/live/dataPath.ts` |
| F7 | `applyLiveUpdate` 只认两种载荷：**二维数组**（首行表头）或完整的 `ChartData`（带 `kind`） | `documentStore.applyLiveUpdate` |
| F8 | **对象数组 `[{月份,销量}]` 会失败**：实测返回 `ok=false`，`liveStatus.error = "header.slice is not a function"`——面板提示里却写着「对象数组即可直接映射」，**这是错的**（我上一轮写的文案 bug） | 实测结论 |
| F9 | 错误原文直接抛给用户看（`header.slice is not a function` 这种 JS 报错对使用者毫无意义） | `applyLiveUpdate` / 面板 |
| F10 | 最小间隔常量重复定义两处：`liveExecutor.MIN_INTERVAL_SEC = 5` 与 `liveSource.LIVE_MIN_INTERVAL_SEC = 5` | 两文件 |

**结论**：请求合并不是「优化项」，是**正确性问题**——一块大屏 12 个图表共用 1 个接口，现在等于给自己开了个压测。

## 3. 子问题 A：对象数组怎么变成图表数据

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A1 维持现状** | 只支持二维表 | 零改动 | F8 的坑留着，真实接口九成返回对象数组 |
| **A2 自动推断** | 对象数组 → `[keys, ...rows.map(r => keys.map(k => r[k]))]` → 复用 `matrixToChartData` | 改动极小（一个转换函数），真实接口开箱即用，天然修掉 F8 | 字段顺序 = 首次出现顺序，可能与期望列序不符；嵌套值需要先被路径/`[*]` 拍平 |
| **A3 显式字段映射** | `source.map = { category: "月份", values: [{name:"销量", field:"sales"}] }` | 精确、可读、能改名 | 要 UI（选字段、配系列），配置成本高；字段变化要重新配 |
| **A4 混合** | A2 为默认，A3 作为「高级：字段映射」可选覆盖 | 覆盖 80% 场景且能兜底 | 两套路径都要测 |

**推荐：A4，但分期**——本阶段先做 A2（马上修 F8），A3 放到映射 UI 能不能做好再定（见 Q1）。

> 附带：A2 之后 F9 也要顺手修——错误信息统一转成人话（`返回数据无法映射成折线图数据：缺少字段`），原始报错放进 `console.warn`。

## 4. 子问题 B：路径语法要做到哪一档

| 方案 | 语法 | 能取到 | 风险 |
|---|---|---|---|
| **B1 现状** | `a.b.c` | 固定层级 | 数组只能靠数字下标，取不到「一批值」 |
| **B2 加下标** | `a.b.0.c` / `a.b[0].c` | 固定层级 + 数组定位 | 只是语法糖，解决不了 `rows[*].value` |
| **B3 加通配** | `rows[*].value` → `[10, 20, 30]`；`data[*]` → 整个数组 | 任意层的数组投影，能把嵌套对象数组拍平成列 | 需要明确「通配结果总是数组」的语义；含通配时结果直接当一列数据，不进 `matrixToChartData` 的二维表假设 |
| **B4 迷你 JSONPath** | `$..rows[*].value`、切片 `[0:5]`、过滤 `[?(@.x>1)]` | 强大 | 自写解析器 + 过滤语义 = 一个子项目，收益低 |

**推荐：B3**（dot + 可选 `[n]` + `[*]`），并明确三条规则：
1. 路径中出现 `[*]` → 结果是**扁平数组**，每项继续按剩余路径取值；
2. 结果数组元素是对象 → 交给 A2 的对象数组推断；是标量 → 当作单列（配合 `category` 自动生成序号）；
3. 路径解析失败统一报「路径 `xxx` 在返回数据里取不到值」，不再是 `undefined is not a function`。

## 5. 子问题 C：请求合并与调度

| 方案 | 做法 | 收益 | 代价 |
|---|---|---|---|
| **C1 执行器内合并** | `LiveExecutor` 内部按 `url` 分组：一组一个 timer，一次 fetch 分发给组内各 `dataPath` | 改动局限在一个文件；请求数 = 不同 URL 数 | 跨实例不共享（F2 仍在）：工作台/演示/轮播重建各打一份 |
| **C2 全局数据源中心（推荐）** | 新增 `core/live/dataHub.ts` 模块级单例：`Map<url, Feed>`；`subscribe(url, key, {dataPath, onData})` / `unsubscribe(key)`；`Feed` 自己管 timer、单飞、退避、订阅者集合 | 请求数 = 不同 URL 数，**跨页面/跨执行器也合并**；「测试连接」可复用缓存；一处实现退避与可见性暂停 | 需要处理订阅者增删时计时器的启停、单例在测试里的重置（`__resetForTest()`） |
| **C3 HTTP 缓存协商** | 带 `If-None-Match` / 304 复用上次数据 | 省流量 | 需要服务端配合，收益不确定；与 C2 正交，可后置 |

**推荐：C2**，`Feed` 内部同时具备：

| 能力 | 规则 |
|---|---|
| 合并 | 同 `url` 的所有图表共用一次请求；`dataPath` 各自解析后再分发 |
| 间隔协商 | 组内取**最小** `intervalSec`（有人要 5 秒就 5 秒，顺带给其他人升级，不做加权平均） |
| 单飞 | 上一轮请求未回来时不发新请求，复用在途 Promise |
| 退避 | 失败后间隔 ×2（上限 5 分钟），成功立即复位；错误分发给所有订阅者（各自 `liveStatus` 标 stale，画面保留旧数据——沿用现有降级语义） |
| 可见性 | `document.hidden` 时暂停计时器，恢复时立即 tick 一次 |
| 观测 | 暴露 `feedStats()`（请求次数/失败次数/最近耗时），供测试与调试面板断言 |

**请求次数验收（写进测试）**：3 个图表共用同一 URL、间隔 5s、跑 30s → `fetch` 调用次数 `<= 6`（而不是 18）。

## 6. 端到端数据流（C2 + A2 + B3 合起来）

```
面板保存 source{url, intervalSec, dataPath}
        │  （指纹变化）
        ▼
WorkbenchView.syncLive ──► dataHub.subscribe(url, itemId, {dataPath, onData})
        │
        ▼        （Feed 每组一个 timer，单飞 + 退避 + hidden 暂停）
     fetch(url) ──► payload
        │
        ├─ 按订阅者各自 resolveDataPath(payload, dataPath)   ← B3 通配/下标
        ├─ 形状归一：二维表 | 对象数组(A2) | 完整 ChartData
        ▼
   分发 → documentStore.applyLiveUpdate(itemId, data, status)
        │
        ├─ 成功：写回 spec.data、liveStatus 记时间
        └─ 失败：liveStatus 标 stale + 人话错误、画面保留上一份
```

## 8. 测试策略（TDD，先写红）

| 用例 | 断言 |
|---|---|
| 同 URL 合并 | 3 订阅者 / 30s → `fetch` ≤ 6 次；每个订阅者都收到自己 `dataPath` 的数据 |
| 单飞 | 同一轮 `tick()` 并发两次 → 只发 1 次请求 |
| 间隔协商 | 组内 5s + 30s → 实际请求间隔 5s |
| 退避 | 连续失败 3 次 → 间隔 5→10→20s；成功后复位到基准 |
| hidden 暂停 | 模拟 `document.hidden = true` → 定时器不触发；恢复立即拉一次 |
| 订阅者增删 | 最后一个订阅者退订 → 停止计时器（用假定时器断言不再调用 fetch） |
| 路径 B3 | `rows[*].value`、`rows.0.value`、`a.b.c`、错误路径 → 数组/标量/人话错误 |
| A2 推断 | `[{月份,销量,利润}]` → `category` 型 ChartData，两列系列（**F8 的回归测试**） |
| 混合格式 | 二维表、对象数组、完整 ChartData 三种载荷都能落到同一图表 |

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 全局单例在测试间串味 | 提供 `resetDataHubForTest()`，`beforeEach` 调用；hub 不持有 store 引用（只回调） |
| 间隔协商导致「有人配 5 秒把别人拖快」 | 明确规则并在面板提示「共用接口的图表共用最快间隔」；上限保护：组内最快不得低于 5s |
| 通配路径结果形状不直观 | 面板「测试连接」直接显示解析后的前 3 条结果，所见即所得 |

### 决策结果（2026-11-06）

四项**全部采纳推荐**：A2 + B3 + C2 + 一次性做完。已实施（计划 T17，方案 D25）：

- `core/live/payload.ts`：四形态归一（二维表 / 对象数组 / 纯数值数组 / 完整 ChartData），失败给人话
- `core/live/dataPath.ts`：`a.b`、`rows[0].v`、`rows[*].v`
- `core/live/dataHub.ts`：按 URL 合并、组内取最快间隔、单飞、退避 ×2（上限 5 分钟）、hidden 跳过
- `LiveExecutor` 变为门面（`options` 存在则自持 Hub，否则用应用级单例）
- 面板文案纠正（原先「对象数组即可直接映射」是错的），补路径语法说明

验收数字：3 个订阅者共用 1 个 URL，一轮 `fetch` 调用 **1 次**（此前 3 次）。
