# ChartForge 设计库：DataV 7.0 对齐缺口与优先级

> 状态：**待评审**。本文只做差距分析与优先级建议，不改产品代码；
> 实施须另立执行计划（`docs/superpowers/plans/`）并逐 Task RED→GREEN。
> 事实来源：`docs/superpowers/specs/2026-11-15-datav-7-design-library-reference.md`
> （含 25 张图证）。基线提交：`bd91f68`（Task 13-a 完成后）。
> 分支：`feature/chartforge-datav-lite`；`main` 不合并。

## 1. 结论摘要

| 维度 | 对齐度 | 判断 |
|---|---|---|
| 组件目录与搜索 | **高** | 已超出 DataV 描述的水准（分组 + 本地搜索 + 预览卡） |
| 地图样式预设 | **中高** | 6 个预设，数量已达 DataV 水准；缺「套件绑定」 |
| 主题 token | **中** | 9 组 token，但无状态色/系列色/渐变色/字号规范 |
| 骨架布局资产 | **中低** | 5 个建屏模板 + 2 个区块，但布局不可拖入已有屏 |
| 规范可视化 | **无** | 无文字规范/色彩规范展示板 |
| 样式跨组件复用 | **无** | 只有整元素 Ctrl+C/V，无「复制/粘贴样式」 |
| 收藏 | **无** | 无 |
| 套件概念 | **无** | 主题与地图样式、组件样式互不绑定 |

**一句话判断**：ChartForge 在「找得到组件」这一层已经够用甚至更好；
缺的是**让用户做出一致观感的机制**——即调研稿 §7 提炼的「骨架层 + 执行层」。

**最关键的单个缺口**：**没有「复制/粘贴样式」**。调研稿的核心结论是
「仅有规范展示板不足以保证一致性，必须提供让样式可跨组件复制的执行机制」。
ChartForge 两者都没有，所以哪怕补上规范展示板也解决不了实际问题。

## 2. 现状盘点（`bd91f68` 实测）

### 2.1 左侧导航（7 项）

```
组件 / 数据集 / 变量 / 图表库 / 素材 / 设计库 / 图层
```

DataV 为 6 项（图层/组件库/设计库/全局变量/过滤器/历史记录）+ 底部 3 项
（我的资源/我的收藏/帮助）。

差异：ChartForge 把**素材提升为一级入口**（DataV 素材在设计库内），
且**没有收藏入口**。

### 2.2 设计库面板现有内容

| 区块 | 现有数量 | 代码位置 |
|---|---|---|
| 主题 | **2**（`monitor-dark` 监控大屏·深色、`business-light` 商务数据·浅色） | `src/core/design/library.ts` |
| 区块（ComponentBlock） | **2**（`title-panel` 标题与信息面板、`kpi-group` KPI 指标组） | 同上 |
| 布局背景 | **2 布局**（`monitor-main-side` 主辅分栏、`monitor-grid-2x2` 2×2 数据区）+ **16 装饰素材** | `src/core/design/layoutBackgrounds.ts` |
| 背景预设 | **8**（blueprint-grid / aurora-flow / orbit-contour / minimal-night / teal-depths / violet-matrix / data-paper / coastal-light） | `src/core/design/backgroundPresets.ts` |
| 设计素材 | 用户上传（SVG 清理 / 图片压缩为 dataUrl） | `src/core/design/assets.ts` |

### 2.3 地图快速样式（6 个）

`deep-sea` / `jade` / `sandstone` / `nebula` / `contour` / `parchment`
（`src/core/components/mapQuickStyles.ts`）

每个预设携带完整 `MapQuickStyleTokens`：background、fill(min/mid/max/empty)、
border、label、emphasis、selected、tooltip、accent、atmosphere。
**这是全仓最接近 DataV「可视化套件」的东西**——但它只作用于地图组件。

### 2.4 建屏模板（5 个，带槽位）

`blank` / `grid-2x2` / `main-side` / `three-cols` / `top-banner`
（`src/core/model/templates.ts`，`TemplateSlot` 概念已存在）

**注意**：这与 DataV 的 5 种布局缩略图（单侧栏/居中三栏/左中右不对称/上中下/双栏）
数量与语义高度接近。差别在**使用时机**：ChartForge 只在建屏时可选，
DataV 可在任意时刻拖入已有画布（带「正在向画布添加」提示）。

### 2.5 主题 token 结构

```ts
tokens: { canvas, panel, text, muted, accent, border,
          chartPalette[], titleStyle{}, borderStyle{} }   // 共 9 组
```

且 `applyThemeToScreen()` **只做两件事**：

```ts
screen.themeId = theme.id;
screen.canvas.background = { kind: "color", color: theme.tokens.canvas };
```

即：**不重写任何已有元素的显式样式**（这是刻意的安全设计，
UI 提示语「现有元素位置与显式样式保持不变」）。

## 3. 逐项对齐矩阵

图例：✅ 已具备 ｜ 🟡 部分具备 ｜ ❌ 缺失

### 3.1 骨架层

| DataV 能力 | ChartForge 现状 | 缺口 | 优先级 |
|---|---|---|---|
| 主视觉布局资产**可拖入已有画布** | 🟡 仅建屏时可选（5 模板）；设计库内 2 个「布局」实为预填好面板的区块 | 布局不能追加到已存在的屏；无「主视觉槽」语义 | **P1** |
| 布局带**可替换槽位** | 🟡 `TemplateSlot` 已存在，用于建屏占位 | 布局背景资产不带槽位元数据 | **P1** |
| 5 种布局缩略图对照 | ✅ 5 个模板，概念等价 | 无缩略图预览（建屏时） | P2 |
| 大屏模板（成品整屏） | ❌ | 无成品级模板 | **P2**（或不做） |

### 3.2 规格层

| DataV 能力 | ChartForge 现状 | 缺口 | 优先级 |
|---|---|---|---|
| 文字规范展示板（48/42/26/14/12/80/57 px + 字体） | ❌ | 完全没有；且项目**未定义任何字号体系** | **P1** |
| 色彩规范展示板（主色/状态色/系列色/文字色/渐变 19 色） | 🟡 有 9 组 token，但无状态色、无渐变、无展示板 | token 维度不足 + 无可视化 | **P1** |
| 状态色语义（警告/正常/故障/宕机） | ❌ | 无 | P2 |
| 数字专用字体（Cuprum 类） | 🟡 `KpiWidget` 有大数字，但无专用字体栈 | 无字体规范 | P2 |
| 设计规范作为**可拖入画布资产** | ❌ | 无 | **P2**（见 §5 反对项） |

### 3.3 执行层（最关键）

| DataV 能力 | ChartForge 现状 | 缺口 | 优先级 |
|---|---|---|---|
| **复制配置到剪贴板 / 粘贴样式** | ❌ | 只有整元素 Ctrl+C/V（`documentStore.clipboard`），无「仅样式」复制 | **P0** |
| 地图快速样式跨组件复用 | 🟡 可在同一地图内切换预设，不能复制给另一个地图 | 预设可切不可传 | **P0** |
| 套件（主题 × 地图样式 × 组件样式 绑定为一个整体） | ❌ 三者互不关联 | 无套件维度 | **P1** |
| 套件切换时同步更新可用资产列表 | ❌ | 无 | P2 |

### 3.4 目录层

| DataV 能力 | ChartForge 现状 | 缺口 | 优先级 |
|---|---|---|---|
| 组件/资产搜索 | ✅ 本地搜索 + 分组筛选 + 预览卡 | — | 已完成 |
| 素材 8 类分组（模型/视频/图标/点缀/背景图/背景框/装饰条/插画） | 🟡 16 个装饰素材，**未分组** | 无分类标签 | P2 |
| 素材需切「全部」才能看全 | — | ChartForge 无套件隔离，天然不受影响 | 不适用 |
| **我的收藏** | ❌ | 无收藏功能 | **P1** |
| 我的资源（按分组列） | 🟡 有设计素材上传，但无分组 | 无分组/文件夹 | P2 |
| 面板刷新 / 搜索 / 关闭 三图标 | 🟡 有面板收起；无刷新与面板内搜索 | 缺少 | P2 |

### 3.5 地图层

| DataV 能力 | ChartForge 现状 | 缺口 | 优先级 |
|---|---|---|---|
| 4 种地图粒度（城市级平面/3D省/3D中国/3D地球） | 🟡 有平面 + 2.5D 倾斜两种 presentation；均为省级中国地图 | 无城市级底图、无 3D 地球 | **P2**（工作量大） |
| 倾斜角 / 旋转角 / 视距比例 可调 | 🟡 有 `pitch`（props.presentation= tilted 时） | 无独立 rotate / 视距 | P2 |
| 视图偏移 | ✅ `view.offset` | — | 已完成 |
| 快速样式缩略图横排 + 翻页 | ✅ 6 个缩略图（`MapQuickStyleThumbnail`） | 无翻页（6 个已全展示） | 已完成 |
| 背景色透明 | ✅ `view.backgroundColor` | — | 已完成 |

## 4. 优先级分组

### P0 — 不做则「一致性」问题无解（建议下一个迭代）

#### P0-1 复制 / 粘贴样式

- **内容**：选中元素 → 「复制样式」把**与外观相关的 props 子集**写入内部剪贴板
  （不进系统剪贴板，避免跨应用泄数据）；选中另一个**同类型**元素 → 「粘贴样式」。
- **边界**：仅同 `componentId`@`version` 或同 chart 类型可粘贴；不复制位置、尺寸、id、数据绑定。
- **理由**：这是调研稿 §7「执行层」的核心。没有它，补再多的规范展示板也无效。
- **验收**：单测覆盖「跨类型拒绝粘贴」「位置尺寸不变」「数据绑定不变」；e2e 覆盖两个 KPI 之间粘贴。

#### P0-2 地图快速样式的跨组件传递

- **内容**：地图 Inspector 增加「复制样式 / 粘贴样式」，复用 P0-1 的剪贴板，
  但载荷为 `MapQuickStyleTokens`。
- **理由**：`mapQuickStyles.ts` 已明确设计为「具体色值写回 props」，
  载荷天然可序列化、可跨组件、离线同源——**只差一个复制动作**。
- **验收**：两块地图之间粘贴后，`quickStyle.tokens` 逐字段一致；离线产物同源。

### P1 — 显著提升一致性，工作量可控

#### P1-1 字号 / 色彩规范 token 化 + 展示板

- **内容**：在 `ThemeKit.tokens` 中补充
  `fontScale`（`display/subtitle/body/axis/number` 五档）与
  `statusPalette`（normal/warning/error/disabled）与 `gradients[]`；
  设计库新增一张**只读规格展示板**（仅展示，不可拖入画布）。
- **不做的部分**：不强制改写已有元素（保持 `applyThemeToScreen` 的现有安全语义）。
- **理由**：ChartForge 目前完全无字号体系，跨面板字号靠手填，这是观感不一致的第二大来源。

#### P1-2 布局资产可拖入已有画布，并携带槽位

- **内容**：把现有 5 个 `ScreenTemplate` 提升为设计库资产，拖入时在现有画布上
  **追加**布局骨架 + 占位槽（复用既有 `TemplateSlot` / `PLACEHOLDER_PREFIX`）。
- **边界**：不覆盖已有元素；追加位置可偏移；一次可撤销。
- **理由**：DataV 的「骨架层」正是靠这个成立的；ChartForge 组件已齐，只差入口。

#### P1-3 套件（Suite）维度

- **内容**：新增 `MapSuite` 概念，把「主题 token」+「地图快速样式 id」+「组件默认样式」
  绑成一个整体。设计库顶部加套件下拉（沿用 `mapQuickStyles` 的 6 个 id 作为套件 id）。
- **边界**：套件只影响**新建**元素与**显式套用**，不静默改写存量。
- **理由**：这是 DataV「风格约束维度」的等价物；且能直接把已有的 6 个地图预设
  复用为套件，**几乎不增加新概念**。

#### P1-4 我的收藏

- **内容**：组件卡片 / 区块 / 布局资产加「☆ 收藏」，工作区持久化，设计库顶部加「我的收藏」区。
- **边界**：收藏只存引用（kind + id + version），不复制内容。

### P2 — 锦上添花

- 素材 8 类分组标签
- 面板刷新 / 面板内搜索图标
- 设计资源分组（文件夹）
- 地图 3D 地球与城市级底图
- 状态色语义
- 成品级大屏模板

## 5. 明确反对跟进的部分

| DataV 做法 | 为什么不跟 |
|---|---|
| 设计规范作为**可拖入画布的资产** | 调研稿 §7 已证明它本质是规格卡，**本身不带约束力**；拖进画布只会多一个静态图元素，增加画布噪音。改为「只读展示板」更诚实。 |
| 素材需切「全部」才能看全 | 这是 DataV 因「套件隔离素材类型」而产生的副作用，不是优点。ChartForge 不应复制这个缺陷。 |
| 中英文主标题不同字号（48/42） | 这是特定字体的视觉补偿（钉钉进步体拉丁字形偏小）。ChartForge 若用系统字体栈，照搬会产生反效果。**只借鉴语义层级，不照搬数值**。 |
| 5 款套件命名（晴山蓝/丹霞橙/…） | 与 ChartForge 现有 6 个地图预设语义重叠，强行改名会破坏 `quickStyle.id` 的稳定性。 |

## 6. 建议实施顺序

```
P0-1 复制/粘贴样式（基础能力，P0-2 依赖它）
  ↓
P0-2 地图样式跨组件传递（验证 P0-1 的载荷抽象是否成立）
  ↓
P1-3 套件维度（复用 6 个地图预设，收益最快）
  ↓
P1-1 字号/色彩规范 token 化 + 展示板
  ↓
P1-2 布局资产可拖入 + 槽位
  ↓
P1-4 我的收藏
  ↓
P2 视资源情况
```

理由：先打通「复制」这条通路，再做「套件」这种聚合概念；
否则套件切换时仍然无法把样式传给已有元素，等于半成品。

## 7. 风险与约束

| 风险 | 缓解 |
|---|---|
| 「粘贴样式」误伤数据绑定 | 载荷白名单只含外观 props；单测逐字段断言 `dataBinding`/`frame`/`id` 不变 |
| 套件切换静默改写存量元素 | 沿用 `applyThemeToScreen` 现有语义：只改画布背景，其余需显式套用 |
| 剪贴板写入系统导致跨应用泄漏 | 仅用内部内存剪贴板，不写 `navigator.clipboard` |
| 规范 token 化破坏既有工作区 | 新 token 全部可选，缺省回退到现值；`version` 不升，读取时补默认 |
| 布局追加与已有元素重叠 | 追加时检测重叠并偏移；操作可撤销 |
| 双端不一致 | 所有 token 随 props/screen 持久化，离线 `RUNTIME_CODE` 读同一份，不内嵌第二份注册表 |

## 8. 验收标准（针对 P0，建议先做）

| # | 验收点 |
|---|---|
| B1 | 同类型元素可复制/粘贴样式；跨类型粘贴被拒绝并给出可读提示 |
| B2 | 粘贴后位置、尺寸、id、`dataBinding` 不变；仅外观 props 变化 |
| B3 | 地图「复制样式/粘贴样式」在两次地图间传递 `MapQuickStyleTokens`，逐字段相等 |
| B4 | 离线产物读取粘贴后的样式，与工作台渲染一致 |
| B5 | 粘贴操作可撤销（进历史栈） |
| B6 | 门禁全绿：typecheck / vitest / build / e2e / `git diff --check` 0 |
| B7 | 新增能力有对应单测与 e2e，不留「只验证属性在变」的空洞断言 |
