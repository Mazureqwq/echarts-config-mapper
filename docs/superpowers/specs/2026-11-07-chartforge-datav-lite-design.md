# ChartForge DataV-lite：低代码可视化应用搭建器设计稿

- 日期：2026-11-07
- 状态：头脑风暴阶段设计稿，待用户审阅；不是实现许可或实施计划。
- 目标用户：前端 / 数据开发人员；大屏最终仍通过拖拽、配置与可视化联动快速组装。

## 1. 产品目标

将 ChartForge 从固定图表拼装工作台，逐步演进为**开发者可扩展、离线可交付的低代码数据可视化应用搭建器**。借鉴 DataV 的工作流与资产组织方式，但不追求首期复制其组件数量、3D 地理能力或企业级平台范围。

### 首期成功标准

1. 开发者可注册可复用组件；组件进入同一画布、属性面板、预览、演示和导出流程。
2. 一个数据集可供多个不同类型组件绑定，不因组件数而重复请求。
3. 表格和 KPI 指标卡能使用同一数据集；表格选行可通过蓝图改变 KPI/其他组件的视图。
4. 使用一个主题套件和可复用素材/区块，能快速完成统一风格的示范大屏。
5. 导出的 zip / 单文件 HTML 保持离线、无外链、不使用 eval；旧工作区仍可读取。

## 2. 范围与非目标

### 首期纳入

- 静态数据与 HTTP API 数据；已有请求、数据加工和保存能力优先复用。
- 版本化组件注册表、配置 schema、数据绑定和组件事件/动作声明。
- 通用表格、KPI 卡作为第一批数据组件。
- 设计库：素材、组件、区块、主题套件四类资源。
- 蓝图画布：组件事件、全局变量、条件/字段处理、数据集动作及组件动作。
- 离线发布与旧工作区兼容。

### 暂缓

- 运行时上传并安装任意第三方插件；首期组件随应用构建、受控注册。
- 任意 HTML/CSS/JS 注入单屏；不执行用户保存的脚本。
- 数据库直连、3D 城市/地球、AI 自动生成、多人协作/权限、插件市场。
- 追求大量组件数量；优先验证几个真实组件的完整生命周期。

## 3. 当前基础与主要缺口

现有 ChartForge 已有固定画布与拖放、图表库、图表/文本/图片/形状、背景与布局模板、HTTP 实时数据和加工、工作区保存及离线导出。当前 `ScreenItem` 是固定类型联合，`ItemView` 逐类渲染；`DataTablePanel` 是图表数据编辑器，不是画布上的通用表格组件。

因此平台化的核心缺口是：

- 可版本化注册的组件模型与统一渲染/属性接口；
- 跨 KPI、表格、图表共享的数据集与字段绑定；
- 视觉资产、主题和可复用区块；
- 声明式的组件交互与全局状态；
- 自定义组件被离线发布器安全纳入的方法。

## 4. 目标架构

### 4.1 组件注册表

首期采用**静态/编译时注册**，Vue 组件作为实现，不从工作区数据动态执行代码。组件定义至少包含：

- `id`、`version`、名称、分类、图标/缩略图、默认尺寸；
- 配置 schema（类型、默认值、校验、控件提示）；
- 数据输入 schema 与字段映射能力；
- 声明式事件、动作及 payload schema；
- 编辑器/演示渲染入口、可选自定义 Inspector、导出兼容信息。

组件实例保存稳定的 `componentId + version + frame + props + dataBinding`。画布统一管理位置、尺寸、旋转、层级、锁定、显隐等通用能力；组件只负责自身内容、配置和数据展示。

兼容策略：旧图表、文本、图片、形状先由适配层接入注册表，保留旧工作区读取；不在第一步中强制重写所有存量数据。后续新组件按版本化实例保存，并提供明确的配置迁移策略。

### 4.2 数据源、数据集、组件绑定

采用三层数据流：

1. **数据源**：首期为静态数据和 HTTP API，复用全局请求设置。
2. **数据集**：定义请求路径、刷新周期、取值路径和处理流水线；首期复用已有过滤、选列、排序、限制行数、字段映射能力，并提供响应预览与错误状态。
3. **组件绑定**：组件选择数据集，将字段映射到自己的输入（如表格记录、KPI 数值、图表类别/系列）。

数据集由运行时统一缓存、刷新和报告 loading/success/stale/error，多个组件共享时避免重复请求，并在失败时保留最后一次成功数据。首期不扩展成通用 ETL/SQL 平台。

### 4.3 设计库

四类资源分层管理：

- **素材**：SVG/PNG/WebP、图标、背景、装饰条等可拖入资源；
- **组件**：带配置与可选数据输入的可复用控件；
- **区块**：多个素材和组件组合的可复用小布局，可暴露有限配置项；
- **主题套件**：颜色、字体、图表色板、背景、面板、标题与边框规范。

首期以少量精品内容验证整套工作流：深色监控、浅色经营两套主题；标题、面板、KPI 卡外观及少量背景/装饰素材。资产体积、存储配额和导出打包方式需在实现计划中明确。

### 4.4 蓝图交互

首期直接提供节点连线画布，但严格限定节点类型，避免演变为任意代码执行环境。首批节点：

- 组件事件（例如表格选行、图表选中、按钮点击）；
- 全局变量（有类型与默认值）；
- 条件判断/字段处理；
- 数据集过滤、参数更新、刷新；
- 组件显隐、配置更新、页面切换等动作。

蓝图以可序列化图结构保存，执行器只运行白名单节点/动作，不调用 `eval`。组件仅能通过声明过的输入、事件和动作接口互通。

### 4.5 发布与离线运行

编辑器、演示和导出共用同一组件版本/实例数据。构建时纳入被使用的受控组件及本地资源；zip 和单文件 HTML 都不得依赖 CDN/外链，不使用 `eval`。不兼容导出的组件应在发布前明确报错，不允许静默丢失。

## 5. 第一个纵向验证切片

以一张“经营概览”示例屏验证全部关键边界：

- 单一 HTTP 数据集同时绑定 KPI 卡和通用表格；
- 表格列支持字段映射、格式与基础样式；
- 表格选中某区域，通过蓝图设置全局变量并驱动 KPI/图表筛选；
- 使用一个主题套件与一两个区块完成统一布局；
- 从编辑、预览、演示到离线导出全链路一致；
- 既有图表、文本、图片、形状工作区正常打开。

该切片的重点不是堆功能数量，而是证明“注册组件 + 共享数据集 + 蓝图 + 设计资产 + 离线发布”能闭环。

## 6. 风险与待审问题

- **组件接口过早冻结**：先以表格和 KPI 两种差异较大的数据组件验证 schema，再稳定公共接口。
- **蓝图复杂度膨胀**：限定首批节点；复杂自定义逻辑先由编译时组件封装，不开放任意脚本。
- **离线导出遗漏插件资源**：组件注册时声明运行时资源和导出能力；发布前做资源完整性校验。
- **存量数据迁移**：适配读取优先，增量迁移并加测试，不一次性改变整个 workspace 格式。
- **资产存储超限**：在实现计划中确定格式、尺寸上限、压缩、配额与备份导出策略。
