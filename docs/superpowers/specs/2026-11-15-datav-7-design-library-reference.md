## 1. 定位：设计库与组件库的区别

官方表述：组件通常包含一套默认样式，难以同时满足各类使用场景；设计库中
**每一个标题、面板、地图都经过设计师精心配置和优化**，风格任选、开箱即用、自由组合。

它要解决的现实痛点是：用户常以模板创建项目，但**单个模板所带的数据面板/地图数量
不足以覆盖多元场景**；跨模板取材又会遇到**风格不匹配、页面拼凑感严重**。

⇒ 设计库的解法不是「更多组件」，而是**引入风格约束维度（可视化套件）**，
使「自由组合」与「风格统一」不再互斥。

## 2. 左栏导航结构（图证）

`case-05-open.png` / `my-resources.png` 显示完整一级导航：

```
图层 / 组件库 / 设计库 / 全局变量 / 过滤器 / 历史记录
```

设计库展开后是 **6 个二级分类**：

```
大屏模板 / 地图 / 数据面板 / 标题 / 设计规范 / 素材
```

底部另有 3 个入口：**我的资源 / 我的收藏 / 帮助**。

**关键观察**：设计库是**一个二级导航容器**，而不是一个平铺面板；
它与右侧「页面配置」（尺寸 1920×1080、不透明度、背景色、缩放方式、缩略图）
并存。这一点正文完全没有体现。

## 4. 六类套件内容

### 4.1 大屏模板（`templates.png`、`case-06-suite.png`）

三种：**区域地图模板 / 中国地图模板 / 3D 地球模板**。

图为宽幅缩略图（每张约 4:1.2 的横条），展示的是**完整成品屏**而非区块。
三者骨架高度一致：顶部标题带 + 中部主视觉 + 左右数据列 + 底部状态条。

### 4.2 地图（`maps.png` 及四张细节图）

四类：**平面区域地图 / 3D 省份地图 / 3D 中国地图 / 3D 地球**。

**图证：这四者不是同一底图换皮，粒度不同。**

| 类型 | 图证观察 |
|---|---|
| 平面区域地图 | `map-flat.png` 实为**城市级**底图：3D 建筑体块、路网、河道（珠江）、绿色高亮点位。不是省级。 |
| 3D 省份地图 | `map-3d-province.png` 单省地形起伏（四川）+ 青色辉光描边 + 卫星影像底图 + 市州标注 |
| 3D 中国地图 | `map-3d-china.png` 全国 + 省界 + **南海诸岛小窗** + 地形晕染 |
| 3D 地球 | `map-3d-globe.png` 星空 + 球体 + **从地表射出的弧线飞线** |

**图证：地图组件的配置面板远比正文丰富**（`map-3d-province.png`）：

- 版本标记 `v3.3.7 / 3D平面地图`
- **快速样式**：横排缩略图 + 左右翻页箭头（说明超过 3 个）
- **视图通用**：视图偏移（水平 `-100~100`、垂直 `-100~100`）
- **视图自然**：视图角度（**倾斜角 30~90**，示例 40.9）、旋转角 `-90~90`（示例 90）
- **视图缩放**：视距比例 `0.5~2`（示例 0.77）
- **屏幕像素**：背景颜色 `rgba(30,34,40,0)`
- **场景交互**：拖拽 / 缩放两个开关
- 底部动作：**复制配置到剪贴板** / **粘贴样式**

最后两个动作是全局机制，见 §7。

### 4.3 数据面板（`panels.png`）

正文举例「数字翻牌器、饼环图、折线柱状图、进度条指示图等」。**图证实际有 8 种**：

1. 三环仪表盘（62% / 83% / 37%）+ 右侧三行指标列表 + 单位
2. 横向色带进度条 + 下方两组四列指标
3. 墨绿底指标行 × 4（每行「标题数据 + 74.8」）
4. 柱状图 + 底部三指标（74.8 / 19.2 / 6）
5. 双色折线图
6. 环形进度（7）+ 三行指标
7. 带标记点的折线（69.8 / 69.71）
8. 数据项进度条列表（data content 1# × 4 + 数值 400/100/190/90）

### 4.4 标题（`titles.png`）

正文说「一级/二级/三级标题」。**图证实际 6 种，且装饰性差异远大于层级差异**：

1. 三级数据标题（绿点 + 短横线）
2. 三级数据标题（绿色三角箭头）
3. 二级数据标题（斜切折角 + 英文副标 Secondary Data Title）
4. 二级数据标题（左侧闪电图标 + 深色底）
5. DAV 一级标题（双翼 + 曲线装饰）
6. DAV 一级标题（下凹曲线）

⇒ 「一二三级」这个分类并不足以描述实际资产形态。

### 4.5 设计规范（三张，信息密度最高）

#### 主视觉布局（`spec-layout.png`、`case-07-layout.png`）

`spec-layout.png` 是**碧玺绿·主视觉居中布局**拖入画布后的实际效果：

- 顶部标题带（含 DAV 标识）
- 中部「主地图区域」大空槽
- 左右各 3 个堆叠面板槽（共 6 个）
- 底部时间条（`2023-03-22 16:53:10`）
- 添加时顶部浮出提示：「正在向画布添加：碧玺绿-主视觉居中布局」

`case-07-layout.png` 显示**共 5 种布局缩略图**：单侧栏、居中三栏（本案例使用）、
左中右不对称、上中下、双栏。

**关键性质：布局资产决定骨架，且带占位槽位**（「主地图区域」是可被替换的槽，
不是静态图）。这与普通背景图有本质区别。

#### 文字规范（`spec-text.png`）

正文只写「文字规范」四字。**图证给出完整规格表**：

| 用途 | 字号 | 字体 |
|---|---|---|
| 主标题 / 中文 | **48px** | 钉钉进步体 Normal |
| 主标题 / 英文 | **42px** | 钉钉进步体 Normal |
| 二级标题 | **26px** | 阿里巴巴普惠体 Normal |
| 表格 / 文本 / 单位 | **14px** | 阿里巴巴普惠体 Normal |
| 轴标签 / 图例 | **12px** | 阿里巴巴普惠体 Normal |
| 主要数据翻牌器 | **80px** | **Cuprum** |
| 次要数据翻牌器 | **57px** | **Cuprum** |
| 交互组件文字（选中/悬浮） | **26px** | 阿里巴巴普惠体 **Bold** |

两个易忽略细节：

- **中英文主标题字号不同**（48 vs 42）；
- **数字翻牌器用 Cuprum 而非中文字体** —— 这是大屏数字观感的关键。

#### 色彩规范（`spec-color.png`）

**图证给出 6 组共 19 个色值**：

- **主色**：`#78FCCD`、`#58CEFF`、`#78FCCD`
- **状态色**：`#FF5D88`（警告/上涨）、`#4EFA7F`（正常/下降）、`#FF903C`（故障/持平）、`#4C4C4C`（宕机/置灰）
- **背景色**：`#151515`；**组件背景色**：`#151515`（两者标称同值，但图上分别呈深灰与墨绿 ⇒ 组件背景另有叠加层）
- **系列色**：`#FFDCB2`、`#FF903C`、`#84c2ff`、`#52FDF2`
- **文字色**：`#D7FDDC`（标题）、`#FFFFFF`（次标题）、`#B3B3B3`（标签/轴色）、`#4EFA81`（选中色）
- **渐变色**：`#1ECE6C-2DEA72`、`#2EDA74-1CE7EF`、`#73FCE0-F5B172`、`#010100-5B5B5B`

### 4.6 素材（`materials.png`）

8 类：**模型、视频、图标、点缀、背景图、背景框、装饰条、插画**。

正文注明「可视化套件下暂未区分素材类型，请在左上角下拉选择『全部』进行查看」。
`materials.png` 证实：切到「全部」后才出现**左侧的分组标签列**（模型/视频/图标/…），
右侧是 2 列卡片瀑布流。

### 4.7 两个跨套件模块

- **我的资源**（`my-resources.png`）：工作台下的设计资源。图证显示左侧有**分组列**
  （全部 / 0230… / 0220 / dev / test / 测试 / 未分组），右侧为缩略图瀑布流。
  正文注明**不受当前套件类型影响**。
- **我的收藏**（`my-favorites.png`）：已收藏组件。图证显示同样是分组列
  （全部 / 测试… / 未分组）+ 缩略图流。正文注明**不受套件类型影响**。

注意两者图标不同、位置相邻，但**分组标签的语义不同**：我的资源按项目/分组，
我的收藏按来源/未分组。

## 6. 官方搭建链路

正文给出 12 步，顺序值得注意：

```
创建工作台 → 选择模板 → 空白看板 → 左栏「设计库」
  → 选套件（碧玺绿）
  → 设计规范 → 主视觉居中布局          ← 先定骨架
  → 地图 → 3D省份地图（拖拽贴合主地图区）  ← 再主视觉
  → 标题 → 契合背景块上方               ← 再标题
  → 数据面板 → 逐个调尺寸样式            ← 再数据
  → （可选）素材美化                    ← 最后点缀
  → 预览
```

**先布局 → 再主视觉地图 → 再标题与数据面板 → 最后素材**。
`case-08-map.png`（插入地图后左右 6 个槽位仍空）→ `case-09-title.png`
（6 个二级标题就位、面板仍空）→ `case-10-panels.png`（面板填满）三张图
完整记录了这个渐进过程。

## 7. 关键机制提炼

看完全部图片后，可以提炼出设计库真正的三层机制 —— **这一层是正文完全没有的**：

| 层 | 载体 | 作用 | 证据 |
|---|---|---|---|
| **1. 骨架层** | 主视觉布局资产 | 决定空间骨架，带可替换槽位 | `spec-layout.png`（6+1+1 个槽） |
| **2. 规格层** | 文字规范 / 色彩规范 | 可查阅的**规格展示板**，本身不是自动约束 | `spec-text.png`、`spec-color.png` |
| **3. 执行层** | 复制配置到剪贴板 / 粘贴样式 | 让规格真正落到组件上的**跨组件复制机制** | `map-3d-province.png` 底部两按钮 |

**这是本文最重要的一条结论**：

> 仅有「规范展示板」不足以保证一致性。必须同时提供
> **让样式可跨组件复制的执行机制**，否则用户看完规范仍会做出不一致的东西。

（正文把「设计规范」描述成可拖入画布的资产，容易让人以为它自带约束力；
图证表明它本质是**可视化的规格卡**，一致性靠的是第 3 层。）

## 8. 成品解剖（`case-12-preview.png`）

最终预览是 **11 区块**：

```
┌───────────────── 顶部主标题带（DAV 双翼） ─────────────────┐
│ 左列 3 面板        中央 3D 省份主地图        右列 3 面板     │
└──────────────────── 底部时间条 ────────────────────────────┘
```

左右面板**严格对齐、等宽等高**——这由「主视觉居中布局」资产直接决定，
而非用户手工对齐。「布局资产 → 成品结构」的因果关系在此闭合。

## 9. 与 ChartForge 的关系

本文只做事实记录。ChartForge 的对齐缺口、优先级与建议顺序见
`docs/superpowers/specs/2026-11-15-chartforge-design-library-gap-alignment.md`。

一句话指向：ChartForge 目前有「套件雏形（6 个地图快速样式）」与「规格雏形
（主题 token）」，但**缺少骨架层资产与执行层复制机制**，且规范未以可视化形态呈现。
